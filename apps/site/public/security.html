Security

Veil is a credential broker for agents and the humans who run them. It is in public beta — open signup plus org invites, 100 free uses per month, and a $1/month Pro Beta. This page is what we can already answer for, in plain terms.

Where secrets live

  • Every secret is encrypted under a per-organization master key. Org masters are wrapped by a deployment key-encryption key held outside the database.
  • A database dump without the KEK is ciphertext — the two are escrowed in separate failure domains.
  • Items, grants, agents, and sessions are per-org. Authorization checks are org-scoped and fail closed.

What agents can see

  • Agents never receive plaintext secrets — not in API responses, MCP, logs, or audit. Secrets are injected into the request/fill path and scrubbed from upstream response bodies and headers.
  • Grants are use-scoped and bounded: item, level, expiry, and max uses. Every use consumes a session use and writes an audit row in the same transaction — a secret never leaves unaudited.
  • Provider key-management endpoints (such as /api-keys on Resend, /v3/api_keys on SendGrid, and /api/personal_api_keys on PostHog) are blocked at grant evaluation (reason="management_endpoint") so an agent granted use cannot mint or delete provider keys.
  • Honey tripwires (--honey --tag veil:honey-revoke) deny and audit on touch, and immediately revoke the offending agent principal (reason="honey_tripwire agent=<id>"), invalidating all of its sessions and grants.

Workload Federation, Outbound WIF & Rotation

  • Agents and cloud functions authenticate to Veil using short-lived OIDC tokens from Vercel, GitHub Actions, Fly.io, Better Auth, Clerk, WorkOS, or Ory Hydra — eliminating long-lived static tokens in environment variables.
  • Agents are distinct principals (PrincipalAgent vs PrincipalHuman), never sharing a human's personal session. Every fetch, fill, and item_rotated row in the append-only audit log records the exact agent_id and approval_id.
  • Optional RFC 9449 DPoP (dpop+jwt ES256) proof-of-possession binds requests to an ephemeral P-256 key (htm, htu, ath, jti replay cache, and cnf.jkt / first-use key pinning) so a captured token cannot be replayed or downgraded.
  • Passkey private keys (WebAuthn P-256) stay sealed inside the vault and only sign assertions after local Touch ID or remote device approval (POST /v1/fill/request).
  • OIDC discovery and JWKS fetches enforce a dial-time SSRF guard that resolves DNS once, blocks RFC1918 private networks, CGNAT (100.64.0.0/10), link-local/cloud metadata (169.254.0.0/16), and non-explicit loopback rebinds, and dials the validated IP directly.
  • For providers supporting RFC 7523 jwt-bearer Workload Identity Federation (such as Anthropic), Veil mints short-lived assertions and exchanges them for ephemeral access tokens — so Veil never stores a static upstream provider API key.
  • Broker-side rotation (veil rotate) runs a dual-phase state machine inside the sealed envelope: mints and verifies the replacement key, commits the new ciphertext and rotate audit row locally, and only then retires the previous pending key.

Identity

  • Humans authenticate through Ory Kratos (password + TOTP), tokens through Ory Hydra, org owner/member checks through Ory Keto. We do not hand-roll identity.
  • Signup is open during the public beta; org owners can also invite an email — the invite carries a one-time recovery code.

Operations

  • Daily encrypted-at-rest dumps of every backing database, with restore drills run against real artifacts; offsite copies land in object storage on a separate failure domain.
  • Audit rows are append-only, exported hourly offsite, and retained on a fixed schedule; deleting an org purges its vault data but never its audit history.
  • Billing enforcement is local and fail-closed: metered use is counted per organization, plan state is confirmed by signed webhook, and a billing outage never becomes an auth outage.
  • Edge and origin both terminate TLS with valid certificates (strict mode, no HTTP path).
