01 — Principal separation (agents are not you)

veil agent bind trusts short-lived OIDC tokens from Vercel, GitHub Actions, Fly.io, Better Auth, Clerk, or WorkOS — and veil agent hydra issues a dedicated client credential for Cursor, Claude Code, Grok, Muse, and devin-cli. Agents are distinct principals (PrincipalAgent vs PrincipalHuman), never sharing your personal login session.

02 — Grant, rotate & outbound WIF

The owner grants use, not possession. Agents see item names and URIs via list_items and match_items — never plaintext. veil rotate rolls keys on Resend, SendGrid, and PostHog with dual-phase overlap, or exchanges short-lived RFC 7523 assertions for Anthropic WIF (--service-account-id svac_...) so Veil never stores a static provider API key.

03 — Brokered API use, browser fill & passkeys

fetch injects credentials at the edge and blocks provider key-management endpoints. For browser & OS sign-ins, Veil fills logins, TOTP codes, and sealed WebAuthn P-256 passkeys after local Touch ID or remote device approval (POST /v1/fill/request).

The boundary

  • Agents never receive secrets. Not in JSON, MCP, logs, or audit records — the transport doesn't carry them.
  • Death to static env keys & token replay. Authenticate via ambient OIDC (createAmbientClient), constrain tokens with RFC 9449 DPoP (dpop+jwt ES256 proof-of-possession), or run veil mcp --self-host as a single binary.
  • Forensic audit & honey tripwires. Every fetch, fill, and item_rotated row in GET /v1/audit/events records the exact agent_id and approval_id. Honey items (veil:honey-revoke) revoke compromised agents on first touch.
  • Humans stay in the loop. Remote approval for level-1 use and passkeys; single native Touch ID prompt before anything leaves your Mac; Ory Kratos + Hydra + Keto for identity.
