# Agents

Bearer is the agent (Hydra `client_credentials` JWT). The host is not identity.

## Surfaces

| Surface | Operations |
| --- | --- |
| OpenAPI | `GET /v1/items`, `POST /v1/use` |
| MCP | `list_items`, `match_items`, `fetch`, `check`, `approval_status` |
| CLI | `item list` is owner; `use --body-file` is the agent fetch |
| SDKs | generated from the spec |

`useItem` / `fetch` / `use --body-file` send method, headers, and body. The broker injects the credential. The response is the upstream result with vault secrets scrubbed.

- `match_items` — which granted item covers a URL (pick the right `item` for `fetch`).
- `check` — dry-run the decision without calling the upstream or touching the secret; on `need_approval` it files the ask and returns `request_id`.
- `approval_status` — poll that `request_id`: `open`, `approved`, `denied`, `expired`. Retry `fetch` once approved.

There is no `GetSecret`. `gen`, `write`, `audit`, and `run` are not coding-agent tools.

## Connect

```
veil agent add cursor
veil agent hydra cursor --secret-file ./cursor.hydra
veil agent token cursor --secret-file ./cursor.hydra --out-file ./cursor.jwt
veil grant add --agent cursor --item stripe --level level2
veil mcp config
```

## Token lifecycle — read this

Minted JWTs expire in **~1 hour**. An expired JWT gets `401 invalid token` on every call — this is the failure most integrations trip on.

The durable credential is the **Hydra client secret** (`cursor.hydra`), not the JWT. Two refresh paths:

**Agent host has the veil CLI** — remint on a timer or on 401:

```
veil agent token cursor --secret-file ./cursor.hydra --out-file ./cursor.jwt
```

**Cloud agent, no CLI** — mint directly from Hydra's public token endpoint:

```
curl -X POST https://id.veil.nyc/oauth2/token \
  -u "agent-cursor:$SECRET" \
  -d "grant_type=client_credentials&scope=veil"
```

`agent-cursor` is the client id (`veil agent hydra` prints it). Cache the returned `access_token` until its `expires_in` nears zero; do not mint per request.

If the agent lost its secret file, re-run `veil agent hydra cursor --secret-file ... --force` — the old secret is rotated out.

## Zero-Secret-Zero OIDC Federation (`agent bind`)

Workloads that already have an OIDC identity (GitHub Actions, Fly.io machines, or apps signed in through Better Auth, Clerk, or WorkOS) do not need a Hydra client secret or any `VEIL_*` secret in environment variables. Bind the agent to the external issuer:

```
# GitHub Actions (binds https://token.actions.githubusercontent.com + repo:org/repo:ref:refs/heads/main)
veil agent bind ci --preset github-actions --repo VortexNYC/veil

# Fly.io machine OIDC
veil agent bind worker --preset fly --org vortex --app worker

# Better Auth / Clerk / WorkOS / custom OIDC issuer
veil agent bind web --preset better-auth --issuer https://auth.example.com --subject service-web
```

`veil agent bind` works against both a local vault and `VEIL_ORIGIN` (`POST /v1/agents/{name}/bind`).

## Self-Host (Single Binary, No Docker)

For hobby projects, homelabs, or air-gapped runners, `veil mcp --self-host` runs the full MCP + `/v1/*` broker as a single binary backed by local SQLite (`~/.veil`) or Postgres (`VEIL_POSTGRES_DSN`) without Kratos, Hydra, or Keto:

```
veil init
veil item add resend --uri https://api.resend.com
veil agent add ci
veil agent bind ci --preset github-actions --repo you/app
veil grant add --agent ci --item resend --level level2
veil mcp --self-host --listen 0.0.0.0:8080
```
