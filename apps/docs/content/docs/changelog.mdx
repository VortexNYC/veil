Veil is in private alpha. Breaking changes land without notice until `v1`.

## 2026-10-22 — OIDC Workload Federation, Outbound Anthropic WIF, Dual-Phase Rotation & Self-Host

- **OIDC Workload Federation (`veil agent bind`)**: First-class presets for **Vercel** (`--preset vercel`), **GitHub Actions** (`--preset github-actions`), **Fly.io** (`--preset fly`), **Better Auth**, **Clerk**, **WorkOS**, and custom HTTPS OIDC issuers. Supports subject-prefix wildcards, custom claim rules (`--claim owner_id=team_...`), `veil agent verify-issuer` (`POST /v1/workloads/verify-issuer`), `veil agent workloads` / `veil agent unbind`, and DB-level `org_id` isolation.
- **Zero-Env Ambient OIDC in `@vortex-api/veil`**: `createAmbientClient({ request })` and `ambientOidcToken` resolve `x-vercel-oidc-token`, `VERCEL_OIDC_TOKEN_FILE`, `VERCEL_OIDC_TOKEN`, GitHub Actions `ACTIONS_ID_TOKEN_REQUEST_URL`, and `VEIL_OIDC_TOKEN_FILE` / `VEIL_OIDC_TOKEN` automatically.
- **Outbound RFC 7523 WIF (`Anthropic`)**: `veil item add --federation-rule-id fdrl_...` and `POST /v1/items` (`wif` object) mint short-lived assertion JWTs from `https://id.veil.nyc` and exchange them for ephemeral upstream provider tokens (`sk-ant-oat01-...`) with in-memory `singleflight` caching (`material.TokenCache`), so Veil never stores a static provider API key.
- **Dual-Phase Broker-Side Rotation (`veil rotate`)**: Zero-touch rotation for `Resend`, `SendGrid` (preserving live key scopes), `PostHog` (`us`, `eu`, `app`), and declarative `/.well-known/key-rotation` (`SpecRotator`) specs, plus assisted rotation (`--secret-file`), separate `--management-item`, scheduled `--interval` rotation, `GET /v1/rotate/providers`, and `veil item verify` (`POST /v1/items/{name}/verify`).
- **Provider Management-Endpoint Blocking & Honey Auto-Revoke**: `grant.Evaluate` blocks agent fetches to registered provider key-management endpoints (`reason="management_endpoint"`). Honey items tagged `veil:honey-revoke` revoke the offending agent principal on first touch (`reason="honey_tripwire agent=<id>"`), invalidating all of its sessions and grants.
- **Single-Binary Self-Host Mode (`veil mcp --self-host`)**: Run Veil on SQLite or Postgres without Ory Hydra/Kratos/Keto (`VEIL_SELF_HOST=1`).
- **RFC 9449 DPoP Proof-of-Possession (`internal/dpop`)**: Sender-constrains short-lived OIDC and session tokens on `/v1/use`, `/mcp`, and principal-authenticated `/v1/*` routes using ES256 `dpop+jwt` proofs (`htm`, `htu`, `iat`, `ath`, `jti` replay cache, `cnf.jkt` + bind-on-first-use key pinning).
- **One-Command 1Password CLI & Authenticator Migration (`veil item import --from-op`)**: Streams logins, passwords, API credentials, TOTP seeds, and credit cards directly from the local signed-in `op` CLI (or newline-delimited `otpauth://` files) and deduplicates against the vault.
- **Passkey Pre-Check, Remote Approval & Single Native Touch ID Dialog**: `passkeyGet` verifies a matching `passkey` item exists before prompting Touch ID, supports `remote_approve` via `POST /v1/fill/request`, and presents a single native macOS `LAContext` Touch ID dialog naming the target site domain (`on <domain>`).

## 2026-09-24 — Customer lifecycle, DR proof, monitoring

- **Org lifecycle is live.** Owner-gated `DELETE /v1/members/{id}`,
  `POST|DELETE /v1/members/{id}/owner`, self-delete `DELETE /v1/me`, and
  org teardown `DELETE /v1/org` — purges all vault rows in one
  transaction, audit survives as forensic record.
- **Invites join the inviter's org.** Provisioning now honors the Kratos
  org stamp only when the Keto member tuple exists; otherwise a fresh
  org is minted.
- **Backups are offsite.** Daily dumps of all four databases land on the
  Railway volume *and* Cloudflare R2 via the `backup-ingest` worker.
  KEK stays separately escrowed — no single vendor loses both.
- **Monitoring covers silent failure.** `veil-monitor` alerts on stale
  backup/sweep heartbeats, `/ready` failures, audit-outbox backlog, and
  sustained origin 5xx (rolling `errors_5m` window in `/ready`).
- **`/privacy` is live** — what we collect, retention, deletion rights,
  and plain-English alpha terms.

## 2026-09-23 — Private alpha surface

- **Invite-only access.** Self-service registration is off. Org owners invite
  with `veil human invite EMAIL`; the invitee's branded setup email arrives
  from `noreply@veil.nyc` and the link is their account setup. Re-inviting
  resends.
- **`POST /v1/invites`** added to the OpenAPI contract. Owner-authenticated;
  returns `identity_id` and `emailed`. Not MCP.
- **Email is Cloudflare Email Sending** behind `mail.veil.nyc` (Bearer-authed
  Worker, React Email templates, multipart text+HTML). Resend removed.
- **First-party Hydra client is `veil`.** The legacy `password-manager`
  client and `password-manager` audience are deleted; agent `.hydra` files now
  record their own audience as JSON.
- **Env vars are `VEIL_*` everywhere.** The `PWM_*` compatibility bridge is
  removed — rename before upgrading.
- **`veil.nyc/` is a landing page**, and `curl -fsSL https://veil.nyc/install.sh | sh`
  installs the CLI and prints the full setup path.
- Login at `login.veil.nyc` no longer offers self-registration; direct visits
  to `/registration` explain invite-only alpha instead of a raw error.
- Keto, Hydra admin, and Kratos admin are internal-only — the stray public
  Railway domains are deleted.
- **Invite emails carry the recovery code.** The setup page asks for a
  one-time code; the invite now includes it alongside the link.
- **Browser fill ships in the CLI.** `veil fill install` registers the
  `nyc.veil.fill` native host and writes the Veil extension to
  `~/.veil/extension` — load unpacked at chrome://extensions (Developer mode).
  Touch ID gates every fill; secrets never sit in `browser.storage`.

## Agents

Agent tokens mint `aud=veil`. If a `.hydra` credential file predates the
audience migration it still reads — bare legacy files resolve to the audience
they were bound under. `veil agent hydra <name> --force` rotates a binding
onto `veil` explicitly.
